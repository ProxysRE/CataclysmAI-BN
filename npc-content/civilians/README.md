# Dialogue integration with the bundled Civilians mod

Current strategy supersedes the initial standalone civilian layer. Source BN c621aaf42fa182473aad10feea2b55647704dcf1 already provides Civilians. The engine patch now changes only data/mods/Civilians/civilians.json; data/json/dda_civilians.json and the port's duplicate GROUP_CIVILIANS_UPGRADE are absent. Civilians stays optional and is not enabled automatically. Existing complete NPC/quest content elsewhere in this project is independent of this ambient-human mod.

All original definitions, faction relations, ammunition, attacks, drops, health, movement, flags and evolution remain byte-equivalent at the parsed-field level after removing the added civilian_chat property. Other mod JSON, Lua and graphics definitions are unchanged. In particular, stock petrified-person speed remains 0, parent remains the stock gawky guardian, and the existing half-life/survivor evolution groups remain in effect. The discarded standalone 90600-weight DDA evolution table is not installed or combined with the mod's groups.

Six existing types receive DDA's read-only response graphs: panicked person, petrified person, parent, officer, knife fighter and hospitalized person. The last three extend the content coverage using BN counterparts instead of duplicate monsters. The source hospital conversation explains the person's condition; it does not create a cure or quest. Portraits are omitted. Random source line variants and response edges remain; display substitutes literal <freaking>/<punc> tags with 'freaking'/an exclamation point. The graph is explicit per concrete type and is cleared when absent on a derived definition, so unrelated children and experienced survivors do not inherit panic dialogue.

Chat uses BN's existing action menu and uilist. A living nonhostile type with a graph must be visible within two tiles on the same floor. No fake NPC, trade, follower orders or effects are introduced. No conversation state is saved. Stock Civilians spawning, Lua behavior and source balancing are preserved; compatibility tests have to exercise the real mod.

The adapted eldercare dependency report now names Civilians as an optional-mod dependency. Its providers are not claimed as core BN content. Complete nursing-home/retirement generation remains disabled: two unique DDA armed types and three mixed/timed location groups still require adaptation. No source rifle officer or gunner is silently mapped to a role with a different personality.

Source provenance: civilian_topics.json is pinned DDA; bn_mod/* matches the official pinned BN Git blobs and is SHA256-authenticated in SOURCE_MANIFEST.json. The native chat baseline is NPCTALK.part*, checked against official Git blob 11a79b1f911775d23ad7f0049725b3de7d43fabf. Windows preflight compares these files with its pristine checkout.

Validation: source graphs and exact preservation of every stock field; no duplicate core declarations; patch composition; package equality and rejection of stale core civilian JSON. Native source and installed tests run separately with Civilians disabled ([dda_npc]) and enabled ([dda_civilians], --mods=civilians). Tests prove core absence, loaded dialogue, preserved faction/evolution profiles and no accidental inherited chat. Full Windows/installed runs, menu interaction and gameplay remain pending. The all-bundled-mod registry and collision gate are in audit_bn_mod_content.py; exact-ID checks do not replace semantic counterpart review.

Three additional eldercare population tables are added in a separate optional-mod file. Stock ambient spawning and evolution remain unchanged. The two armed source variants reuse existing officer/survivor types; see ../eldercare/GROUP_ADAPTATION.md. Full eldercare sites remain staged, so these tables do not yet add world placements.

Current native Lua exception: the new Grey Moose lodge uses fixed community NPC placements, so main.lua adds only GMLODGE to the existing exclusion list. Stock groups/evolution/gun/pulping/option code remains unchanged. Full eldercare exclusions remain candidate-only. Packaging validates the exact Lua result; see ../militia/README.md.
