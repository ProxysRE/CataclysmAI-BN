# Pinned BN dependency identifiers

`BN_ID_INDEX.json` describes a checksummed compressed cache in `BN_IDS.part*`, containing 33,085 typed identity records derived from all 1,933 core `data/json` files at BN revision `c621aaf42fa182473aad10feea2b55647704dcf1`. CI regenerates and compares the cache using `export_bn_ids.py`, including its source-file fingerprint.

This is a presence index, not a semantic compatibility claim. It covers JSON declarations, abstract identities, nested mapgens, vehicle-part shapes generated by the pinned BN loader, vehicle-group aliases accepted by mapgen, and explicitly recognized null sentinels. Other hardcoded or dynamically generated engine identifiers are outside its scope. A missing record is an unresolved JSON-level reference, not proof that no possible engine equivalent exists.

Use it before assuming an item/group exists or creating a duplicate. Fetch the pinned source definition for the selected counterpart, compare its behavior, and run native loading/generation tests before integrating content. Item and item-group namespaces remain separate. The bootstrap emits only public identifier metadata through the text API once; later CI runs validate this committed cache without emitting encoded records.

Use `export_bn_ids.read_cache(path)` to reconstruct the identifier table. Splitting the compressed cache keeps every preserved source file accessible through the text-only GitHub API.
