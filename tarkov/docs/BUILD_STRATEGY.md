# Самостоятельная игра на базе BN

## Решение от 21.10.2026

По предложению пользователя проект развивается как самостоятельная конверсия BN
со своим Windows executable, правилами, запуском, созданием персонажа и развитием.
Это уже не цель «устанавливаемый поверх произвольного BN мод». Закреплённую базу
554950f3635f50ddd1d32c6e1b6e2bdee9842bd6 пока сохраняем. Первый production-патч
0001 уже обязателен для холодной загрузки границ; текущая сборка фактически содержит
собственные изменения движка. Этот выбор не требует нового репозитория прямо сейчас.

Внутренний каталог `mods/trkv_raid_core` пока остаётся модулем данных и Lua.
Его расположение не определяет формат конечного продукта. Перенос файлов в core
не добавляет возможностей движка и не является отдельной целью. В конечном запуске
нужные модули должны подключаться самим проектом, без ручного выбора мода игроком.
Автоподключение и отдельный экран старта ещё не реализованы.

## Что позволяют данные, а что меняет движок

| Задача | Возможности BN и выбранное направление |
|---|---|
| Только BEAR и USEC при создании персонажа | JSON profession и whitelist professions у сценария позволяют ограничить список |
| Скрыть ванильные сценарии | В BN есть whitelist сценариев; удалять все исходные определения не обязательно |
| Стартовое снаряжение | Profession/itemgroup задают комплекты; независимый набор «издание × сторона» требует собственного явного выбора и выдачи |
| Выбор «Издание → Сторона ЧВК» | Переделываем существующие вкладки: scenario → издание, profession → сторона; новый экран с нуля не нужен |
| Названия и определения навыков | Часть задаётся JSON; это ещё не новая модель развития |
| Опыт за действия, рост, бонусы, ограничения и связь с боем | Общая логика роста уже в C++; потребуется аудит мест применения и собственная реализация |
| Рейды, содержимое карт, добыча | Сохраняем текущие JSON/Lua там, где их достаточно |
| Недоступное действие/событие, ИИ и правила симуляции | Изменяем C++ и bindings по мере подтверждённой необходимости |

Данные позволяют сделать упрощённый вариант как мод. Для намеченного масштаба
собственный движок не должен быть запрещённым исключением. При этом переписывать
работающие системы BN без конкретной причины не нужно.

## Создание персонажа: две независимые сущности

- Порядок: сначала издание на существующем экране сценария, затем сторона ЧВК
  `USEC` или `BEAR` на существующем экране профессии. Отдельный экран с нуля не требуется.
- Издание: самостоятельный выбор стартовых условий. Точный список и баланс
  изданий ещё не заданы; не выдаём придуманные наборы за утверждённые.
- Будущие данные профиля хранят независимые стабильные ID стороны и издания,
  с версией схемы. Не выводим их из переведённой подписи или имени profession.
- Таблицы комплектов связывают издание со стороной. Одежда, оружие и склад
  могут различаться, но один комплект не должен быть продублирован двумя выдачами.
- Начальная выдача выполняется только при создании нового профиля. Эвакуация,
  перезапуск, поражение или повтор загрузки не выдают стартовые вещи заново.
- Создание профиля и выдача стартового комплекта требуют отдельного теста
  сохранения/повтора; существующие тестовые персонажи не конвертируются молча.
- Обычные очки, свободный набор профессий/черт и распределение навыков BN
  не должны оставаться обходом проектного процесса создания.

Это контракты следующего этапа, а не уже реализованное меню.

## Навыки: не сводить перенос к переименованию

В BN SkillLevel::train и SkillLevel::rust задают рост и деградацию. Навыки также
применяются другими системами игры. Прежде чем удалять или заменять ID, составляем
карту зависимостей: бой, движение, медицина, крафт, взаимодействия и ИИ.
Целевой список навыков, способы получения опыта и бонусы согласуются отдельно.
Где нужны внутренние навыки BN, используем явно описанный адаптер, а не скрытую
вторую систему прогрессии игрока. Профиль и миграции сохраняют накопленное развитие.

## Порядок работ

1. Закрыть первый слой рейда: текущие Windows native/cold проверки, русский пакет,
   затем один объединённый пользовательский прогон. Не тестировать лампы отдельно.
2. Продолжить основу противников по прежней последовательности слоёв.
3. Самостоятельный запуск и переработку создания персонажа выполнить позднее:
   издание → сторона ЧВК, один стартовый комплект, сохранение выбора. Не вставлять
   новый этап перед противниками только из-за обсуждения будущей архитектуры.
4. Полная новая система навыков и постоянный профиль относятся к развитию; их
   зависимости учитываем до расширения баланса боя и экономики.

Карманы и неразрушаемость геометрии остаются отложенными по прежнему решению.
Новые изменения не должны ломать сохранения или отменять проверенный рейдовый цикл.

## Поддержка собственной игры

Поставляем Windows executable и данные вместе. Обновление BN — управляемый перенос
сравнением исходников, конфликтов и сохранений, а не автоматическая смена nightly.
Собственные изменения изолированы от Narrative и соседнего DDA-порта. Для изменений
формата сохранения заранее нужны версия и миграция. Внутренние библиотеки, предметы
и карты BN сохраняем по необходимости; очистка интерфейса не равна удалению всего
ванильного содержимого из движка.
