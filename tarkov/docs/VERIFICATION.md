## Что проверено настоящим BN

- Инициализация убежища обработчиком мода, затем контрольное сохранение/загрузка
  в убежище без перехода между измерениями.
- До и после контроля: AR-15, повреждение 1375, магазин с 17 патронами, ремень,
  рюкзак, пластиковая бутылка и две порции воды внутри.
- Вход со снаряжением, получение настоящего предмета с карты, изменение клетки.
- `game::load` восстанавливает персонажа, карту и Lua state в том же процессе.
  Проверены замена вложенной таблицы и работа зарегистрированного callback эвакуации.
- После загрузки в рейде и эвакуации полностью совпадают JSON-снимки оружия
  и рюкзака с эталоном после контрольной загрузки. Поля из сравнения не исключаются.
- Повторная загрузка настоящего checkpoint `cleanup`, записанного перед сбросом:
  load hooks не меняют его; первый последующий тик завершает очистку один раз.
- Новый рейд восстанавливает добычу и изменённую клетку.
- Поражение теряет переносимые тестовые вещи; таймаут завершается через `recover`.
- Обнуление HP аватара и настоящий `is_dead_state()` запускают death hook:
  персонаж остаётся жив, возвращается в убежище, пакет потерян.
- Настоящий отказ записи SQLite при эвакуации, через временный trigger: нет
  преждевременной победы, пакет остаётся при игроке, транзакция закрыта.
  После снятия отказа повторный возврат проходит с однократным учётом результата.

- Шкаф убежища: пакет перекладывается из инвентаря, получает строковую метку;
  после поражения, таймаута, death hook и повторной эвакуации остаётся ровно один
  пакет с тем же типом и меткой. Это не полный JSON-снимок содержимого склада и
  не проверка склада после холодного перезапуска.
- AR-15 берётся в руки, рюкзак надевается перед эталонными JSON-снимками. Их
  положение проверяется после входа, загрузки, эвакуации и восстановления cleanup.
  Полное сравнение JSON и потеря обоих предметов при поражении проходят.

## Локальные проверки

- 15 тестов контроллера и 5 тестов зарегистрированных callbacks в Lua 5.4
  с подменённым адаптером BN.
- Отказы возврата/очистки, replay checkpoint, двойное завершение, дедлайн,
  несовпадение измерений, смерть/таймаут после неудавшейся эвакуации.
- Замена таблицы при загрузке, игнорирование смерти НПС, отложенное восстановление
  после снятия запрета записи внутри `game::load`, повторные load hooks.
- Синтаксис Lua, структура JSON, размеры карт, символы и связность ключевых точек.
- Контракт холодной загрузки: ID измерений соответствуют save_prefix их типа.

Эти проверки дополняют игровой прогон, но сами по себе не доказывают исполнение BN.

## Найденные и исправленные ошибки

- `39345635894`: CMake остановился из-за Gettext. Исправлено `LANGUAGES=none`.
- `39402876234` и `39404667202`: C++ собран, проверка данных упала на
  `couldn't parse color: c_light_yellow`. У лампы исправлен цвет на `yellow`.
- `39415234742`: загрузка данных прошла, тест остановился на `package.path must be
  a string`. BN очищает search path после загрузки модов; тест использует живые
  модули из `package.loaded` вместо повторного `require`.
- `39417738221`: все Lua-этапы прошли, два CHECK полного JSON выявили только `owner`
  и `active` у воды. `game::load` назначает владельца, `item::deserialize` активирует
  пищу. Добавлен контрольный reload в убежище; сравнение всех полей сохранено.
  Исправленный тест полностью прошёл в `39420318120`.
- Обращения callbacks к старой таблице и восстановление во время запрета записи
  исправлены до игрового прогона; обе регрессии воспроизводились локально.
- По исходникам `game::load` найден контракт save_prefix для восстановления типа
  измерения в новом процессе. Для имён `trkv_dev01_*` объявлен `trkv_raid_space`.
  Загрузка данных и полный повтор интеграционного сценария с этим типом прошли
  в `39422503315`; холодный старт проверяется отдельно.

## Среда проверки

- Native build кэшируется отдельно от исхода игровых проверок. Точный ключ включает
  базу, C++ harness, installer, helper времён файлов и workflow. CMake/Ninja,
  загрузка мода и игровой тест выполняются каждый раз. В `39422503315` точный cache-hit
  подтверждён: Ninja сообщил `no work to do`; шаг сборки завершился за 27 секунд
  по метаданным Actions. Это одно наблюдение, не оценка средней производительности.
- Диагностические логи выводятся в Actions и сохраняются артефактом.
- Загрузка мода ограничена пятью минутами, native test — пятнадцатью.
  Тест печатает этапы выполнения; таймаут не считается прохождением.

## Первый слой ещё не закрыт

- Подготовлена проверка шести сторон bounds в убежище и рейде, после загрузки
  и повторного рейда: boundary terrain остаётся t_pd_border, а попытка поставить
  t_floor отвергается. Новый тест пока не подтверждён native-прогоном. Он проверяет
  setter и bounds, а не все игровые действия или неразрушаемость внутренних стен.
- Полный перезапуск процесса с загрузкой сохранения, включая правильный тип
  пространства и продолжение рейда/очистки после старта нового процесса.
- Работа терминала и выхода через настоящий интерфейс, проверка на Windows.
- Ошибка входа с отсутствующим/частично созданным измерением может оставить фазу
  `cleanup`, если BN откажет в сбросе. Такой отказ нельзя молча обходить.
- Полный запрет изменения геометрии при сохранении прострелов ещё не реализован;
  аудит и сценарии находятся в GEOMETRY_POLICY.md.
- Смерть от всех возможных причин и взаимодействие с другими модами не подтверждены.
- Очистка НПС/транспорта и производительность больших карт относятся к следующим слоям.

Не использовать старые игровые миры для этих опытов. Lua-ссылки на предметы не должны
переживать смену карты; в storage сохраняются только простые данные. Не объявлять
проверенный replay состояния полной транзакционностью всех операций движка.
