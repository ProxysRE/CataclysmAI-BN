# Дорожная карта

| Слой | Результат / условие завершения | Текущий статус |
|---|---|---|
| 1. Механика рейда | Полный цикл, сохранения, перенос/потеря вещей, восстановление и сброс | В работе; native gate ещё не пройден |
| 2. Основа противников | Создание/очистка НПС, стороны, движение, обнаружение, бой и поиск | Только аудит средств BN |
| 3. Геометрия локаций | Планировки, этажи, проходы, укрытия и границы | После проверки движения и боя |
| 4. Наполнение рейдов | Обстановка, наборы противников, добыча, вариативность и выходы | После геометрии |
| 5. Экономика и прогресс | Склад, торговцы, снабжение, лечение, развитие убежища | После устойчивого цикла рейда |
| 6. Задания | Цели и цепочки на готовых механиках и содержимом | После основы прогресса |

Версия BN, временные правила и зависимости зафиксированы в `DECISIONS.md`.
Техническая карта нужна для проверок первого слоя; это не начало детализации большой
локации. Windows-пакет, длительные проверки и производительность входят в подготовку
выпуска после готовности нужных игровых слоёв.

## Ближайший gate

1. Загрузка JSON и Lua штатным BN.
2. Фактический вход/выход с переносом пакета.
3. Повторный рейд восстанавливает добычу и изменённую клетку.
4. Поражение теряет вещи и возвращает персонажа.
5. Таймаут использует тот же механизм завершения.
6. `game::load` восстанавливает персонажа, карту и состояние мода из сохранения.
7. Полное закрытие и загрузка мира через игру.
8. Проверка checkpoint очистки после загрузки и отказов записи.

Первые шесть покрывает подготовленный native harness, если он успешно выполнится.
Последние два не считать выполненными по Lua-mock тестам.

Работы по документации и отбору материалов могут идти одновременно. Не расширять
предметную экономику до gate целостности вещей; не детализировать большой Завод
до проверки движения и боя на технических аренах.
