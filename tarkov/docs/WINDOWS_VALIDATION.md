## Что подготовить до игрового прогона

Добавлен workflow `.github/workflows/tarkov-windows.yml`: Ubuntu готовит шейдеры
из закреплённых исходников, Windows-2022 собирает MSVC x64 с обязательным патчем.
Зависимости vcpkg закреплены baseline a8f78d257ade3c2e7999c1129a6d29971ae32006.
Первый прогон 39587577518 прошёл шейдеры, но остановился до компиляции на применении
патча из-за разных LF/CRLF в checkout. Installer нормализует patch и целевой файл
в LF; stdin Git получает bytes, без преобразования строк Python на Windows.
Локальный регрессионный тест проверяет восемь комбинаций LF/CRLF и core.autocrlf.
Повторный Windows-прогон 39609962500 успешен.

После успешной сборки артефакт `Tarkov_DEV01_Windows_x64` содержит portable ZIP и
SHA256. Установленные файлы мода сверяются с исходниками; проверяются PE executable,
шейдеры SPIR-V/DXIL, отсутствие зависимости от SDL DLL, --version и --check-mods.
Игру запускают из установленной папки с отдельным временным --userdir, чтобы
не упаковать служебные настройки и сохранения. ZIP создаётся только после успеха.
TARKOV_BUILD.json содержит SHA проекта и BN, хеш exe, патчей и результаты smoke;
windows_ui_verified остаётся false. Исходники модуля и патч включены в project-source.
Это не проверка рейда через Windows-интерфейс и не Windows cold-restart harness.

1. Собрать Windows x64 executable вместе с данными BN и нашим модулем.
2. Проверить --version и загрузку trkv_raid_core через --check-mods в этой сборке.
3. Убедиться, что пакет содержит патч, мод и файл с SHA основы/проекта.
4. Включить мод при создании нового мира; не использовать чужие игровые сохранения.

В официальной pinned .github/workflows/build.yml Windows использует windows-2022,
MSVC x64, vcpkg, предварительную генерацию шейдеров и cmake --install для пакета.
Эти зависимости нужно сохранить при подготовке нашего workflow. Простое копирование
модуля поверх готового штатного BN не включает исправление C++.

https://github.com/cataclysmbn/Cataclysm-BN/blob/554950f3635f50ddd1d32c6e1b6e2bdee9842bd6/.github/workflows/build.yml

## Сценарии через интерфейс

Использовать действия из меню игры и текущие привязки клавиш. Прямой вызов Lua
функции не засчитывает проверку терминала или выхода.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Создать персонажа в новом мире с модом | Персонаж оказывается в тестовом убежище |
| 2 | Взять оружие в руки, надеть рюкзак; оставить контрольный предмет в шкафу | Комплект и предмет доступны через штатный инвентарь |
| 3 | Осмотреть терминал отправления и выбрать рейд | Открывается меню; после выбора появляется рейдовая карта |
| 4 | Забрать тестовый пакет со стойки | Предмет действительно находится в инвентаре |
| 5 | Сохранить игру в рейде и полностью закрыть приложение | Процесс завершён, сохранение остаётся на диске |
| 6 | Запустить приложение заново и загрузить персонажа | Та же карта, оружие в руках, рюкзак надет, пакет сохранён |
| 7 | Проверить края карты и дождаться предупреждения таймера | Граница остаётся закрытой, отсчёт после загрузки не начинается заново |
| 8 | Осмотреть зелёный выход в юго-восточной части карты | Возврат в убежище через действие выхода; комплект и пакет сохранены |
| 9 | Проверить шкаф и переложить добычу | Контрольный предмет на месте, пакеты не дублируются |
| 10 | Повторить рейд | Тестовая добыча появилась заново |
| 11 | Дождаться таймаута, используя игровые действия ожидания | Возврат в убежище с потерей переносимых вещей; содержимое шкафа сохранено |
| 12 | Сохранить убежище, закрыть приложение, загрузить снова | Шкаф и итог рейда сохранены, новый вход доступен |

Для проверки таймера записать время входа и сохранённый deadline из диагностических
данных, если одних предупреждений недостаточно. Сравнивать игровое время; загрузка
не должна выдавать ещё 30 минут. Игра не обязана расходовать игровое время, пока
приложение закрыто.

Смерть и точный checkpoint cleanup уже проверены автоматическим стендом. Проверку
смерти через Windows debug menu можно добавить к протоколу отдельно, не смешивая
её с обычной эвакуацией. Произвольные обрывы записи этим протоколом не покрываются.

## Запись результата

Для каждого прогона сохранить: SHA проекта и BN, способ сборки, --version,
версию Windows, результат каждого шага, debug.log и снимки экрана при сбое.
Вместо общего «работает» указать последний успешный шаг и точное действие,
после которого возникла ошибка. До выполнения шагов статус остаётся «не проверено».

Не добавлять НПС, новые карты или экономику ради этой проверки. Карманы,
защищённый контейнер и неразрушаемость внутренних стен остаются отложенными.

## Исправление русского языка

Первый прогон перевода deab709 завершился ошибками: BN отклонил избыточное
str_pl, а сборка не нашла ru.po (upstream не хранит PO в исходниках).
str_pl удалён; английское множественное число BN выводит автоматически,
русские формы остаются в каталоге мода.
Windows workflow импортирует готовый платформонезависимый каталог из официального
BN 2026-10-19; архив закреплён SHA256. Версия движка остаётся прежней.
LANGUAGES=none отключает только компиляцию отсутствующих PO; готовый MO устанавливается
в обычную папку lang/mo. SOURCE.json и TARKOV_BUILD.json фиксируют источник перевода. В пакет обязательно
входят lang/mo/ru_RU/LC_MESSAGES/cataclysm-bn.mo и data/mods/trkv_raid_core/lang/ru.mo.
Упаковщик читает оба каталога и отклоняет отсутствующий/пустой перевод.
Тексты Lua переводятся locale.gettext при показе; ошибки в сохранениях остаются
исходными строками и переводятся при отображении. JSON использует штатные переводы BN.
Английский остаётся доступен как исходный язык. Язык выбирается в настройках игры.
Новая сборка с русским требует отдельного прогона; визуальная проверка пока не проведена.

## Свет и стены технической карты

Стены карты используют ванильный t_wall, внешняя граница — штатный t_pd_border.
Новые карты используют ванильный f_olight_nogrid (потолочный свет без электросети,
120 единиц света). Ранее применялся f_trkv_test_lamp с постоянным светом 160.
Legacy ID сохранён для уже созданных карт, looks_like указывает на ванильную лампу.
Это не миграция существующего убежища: его лампы сохраняют своё прежнее состояние.
Следующая сброшенная рейдовая площадка получает ванильные лампы.
