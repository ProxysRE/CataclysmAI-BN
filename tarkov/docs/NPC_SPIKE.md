# Следующий эксперимент: один стрелок

Средства BN проверены чтением исходников. После успешного Windows gate первого
слоя (39646723414) подготовлен отдельный native probe участника; его собственный
игровой результат ещё ожидается. Обычные рейды игрока остаются без противников.

## Найденные средства

| Требование | Механизм BN | Граница вывода |
|---|---|---|
| Создать человека с заданным комплектом | JSON `npc` / `npc_class`, `Map:place_npc` | Само по себе не задаёт тактику |
| Задать сторону и враждебность | `Npc:set_faction_id`, `set_attitude` | Отдельно проверить отношения НПС друг к другу |
| Собственный ход | `npc_class.lua_ai` и `game.npc_ai_functions[name](npc)` | `true` заменяет штатный выбор действия; `false`/`nil` передаёт ему ход |
| Наблюдать ход/движение | `on_npc_do_turn`, `on_npc_try_move` | Это разные hooks; do_turn не является заменой `lua_ai` |
| Передвинуть на соседнюю клетку | `Npc:move_to` | Использует настоящую логику движения; нужны проверки дверей и препятствий |
| Рассчитать путь | `Npc:set_move_target` | Обёртка над `update_path`, не доказательство автоматического движения по маршруту |
| Узнать цель штатного ИИ | `Npc:current_target`, `danger_assessment` | Cache обновляется перед `lua_ai`; это не повод читать скрытые позиции всех врагов |

В `npc::move` после обновления cache вызывается `run_lua_npc_ai`. Если Lua вернул
`true`, штатный выбор действия пропускается. Если обработчик при этом не потратил
очки действий, BN обнуляет их, защищая цикл от зависания. Следовательно, простой
`return true` может заставить НПС пропускать действия. Ошибочный тип результата
вызывает диагностику и возврат к штатному ИИ.

У НПС в изученном наборе bindings нет прямой обёртки `execute_action` или `fire_gun`.
Обнаруженная `execute_action` относится к монстрам. Нельзя переносить пример монстра
на человека и считать собственную стрельбу уже доступной.

## Решение для первого опыта

Создать отдельный тестовый класс человека и подключить обработчик только ему.
Попробовать собственный патруль вне боя, а стрельбу, прицеливание и перезарядку сначала
оставить штатному ИИ через `false`. Не менять глобальное поведение обычных НПС.
Это рабочая гипотеза; переключение между патрулём и боем требует проверки.

Для этого ещё не нужны экономика, модели поведения боссов, большая карта или LLM.
Состояние экспериментального участника привязывать к ID рейда и устойчивому ID НПС.
Сохранять простые данные, а не Lua-ссылку на объект. При завершении рейда проверять
отсутствие участников в убежище и их восстановление ровно один раз в новом рейде.

## Порядок проверок

1. Один НПС появляется в рейде, отсутствует в убежище, удаляется сбросом территории.
2. Без цели проходит короткий маршрут, тратит действия и не застревает у двери/стены.
3. При обнаружении игрока штатный ИИ получает управление и действительно стреляет;
   уменьшаются патроны, происходят прицеливание и перезарядка.
4. После разрыва видимости не знает новую скрытую позицию игрока. Поиск, память цели
   и реакцию на звук измерять отдельно, не объявлять готовыми по факту стрельбы.
5. Загрузка внутри рейда восстанавливает того же участника без дублей и бесплатного
   пополнения патронов. Повторный рейд создаёт нового участника с исходным комплектом.
6. Затем добавить второго НПС и проверить дружественный огонь, отношения сторон,
   блокирование проходов и стоимость симуляции. Только после этого проектировать группу.

Фиксировать seed, стартовые позиции, оружие, дистанции, освещение и число ходов.
Для боя нужны несколько seeds и наблюдаемые результаты; один удачный выстрел не
доказывает устойчивость поведения. Патч движка обсуждать по воспроизводимой нехватке
API, а не заранее.

## Подготовленный probe участника

`tests/bn_npc_harness.cpp.inc` и `tests/bn_npc_probe.lua`: один вооружённый НПС,
шаг через живой Lua binding с расходом действий, сохранение/загрузка ID и комплекта,
очистка после эвакуации и поражения. Новая попытка не возвращает старого НПС;
повторный spawn получает новый ID. Данные объекта не сохраняются как userdata.
Тест использует штатный test_talker BN только в стенде, без нового production NPC.
Это ещё не patrol controller, выбор целей или измерение боевого ИИ.

Сценарий не удерживает ссылку NPC между load/travel: в test_data.actor только
кратковременный аргумент move_to, после шага он очищается; между этапами — character_id.
До подтверждения native-результата не считать очистку участников реализованной
поверх доказанного контракта движка.
