# Следующие проверки тактического ИИ

Рабочий план от 26.10.2026. Это критерии будущих опытов, не отчёт об их прохождении.
База BN остаётся 554950f3635f50ddd1d32c6e1b6e2bdee9842bd6.

## Текущий рубеж

Код прикрытия опубликован в 7c12fac5bd4ba21eb79e9c71de0deeb58931b83b.
Windows 40306993933 и Linux 40306993955 ещё выполняются на момент составления.
Сначала проверить этот результат и исправить возможный сбой. Нынешний native
проверяет настоящую стрельбу и расходы, но намерение движущегося союзника
создаётся тестом. Он не доказывает естественный совместный манёвр.

## Блок A: отказ и прекращение прикрытия

Каждый отрицательный опыт вызывает guarded executor отдельно от общей цепочки:
обычный контроллер после отказа вправе выбрать другое законное действие.
Нулевые расходы/неподвижность относятся к самому отказавшему исполнителю,
а не обязательно ко всему решению NPC. Проверять moves, path, позицию,
боезапас и отсутствие лишних предметов/бросков/смены оружия.

| Сценарий | Подготовка и событие | Требуемый результат |
|---|---|---|
| Потеря цели | Стрелок получил законный контакт; цель ушла за стену, cache может оставаться старым | Executor отказывает; зрительная память хранит прежний снимок; поиск не получает скрытых текущих координат |
| Скрытие персонажа | Клетка видима, Creature скрыт | Нет aim/fire по старому current_target; seen_at не обновляется |
| Союзник на линии | Видимый не-враг входит между стрелком и целью | Нет выстрела через него; отказ не расходует патроны; общий контроллер может искать другую позицию |
| Дверь/преграда | Между стрелком и целью закрылась непроходимая преграда | Нет blind fire/прострела из этой ветви; последующий уход цели не раскрывает координат |
| Пустое оружие | Последний реальный патрон потрачен при поддержке | Поддержка прекращается; собственная перезарядка имеет приоритет; патроны не создаются |
| Неполная очередь | Патронов меньше количества выбранного режима | Executor отказывает без частичной фиктивной очереди и без выдачи патронов |
| Чужой снимок | Передана позиция, отличающаяся от актуального видимого target | Native отказывает; read-only проверки не двигают NPC |
| Близкая опасность | Цель сблизилась менее чем на четыре клетки | Нельзя продолжать stationary cover только ради чужого плана; возвращается обычный выбор обороны |
| Авария | Возникло опасное поле или замеченная взрывчатка | Escape выполняется раньше cover; нет второго действия стрельбы в том же решении |
| Конец движения | Peer дошёл и его goal удалён | Следующий выбор больше не назначает поддержку этого плана |
| Отмена/гибель peer | План истёк, отменён, застрял или боец погиб | Роль снимается без продления чужого deadline; погибший не считается живым из-за сохранённой записи |
| Потеря связи | Peer ушёл за стену, на другой этаж или дальше локального радиуса | Нового подтверждения поддержки нет; явной радиосвязи пока нет |

В положительном опыте делать отдельные измерения затрат прицеливания и стрельбы.
Не требовать выстрел каждым действием: законный aim тоже расходует время.
Если фактический расход боеприпаса не произошёл, не объявлять огневой опыт
пройденным по одному trace=cover_fire. Случай заклинивания отделять от расхода
и от ошибок роли, а не ослаблять утверждение о состоявшемся выстреле.

## Блок B: два действующих NPC вместо seed-намерения

1. Создать двух зарегистрированных бойцов одной стороны/отряда с настоящими
   профилями и комплектами. Сохранить их ID, исходное оружие и количество патронов.
2. Обоим дать возможность самостоятельно наблюдать цель; выбрать стартовую
   геометрию, где один может получить законный короткий манёвр, а другой —
   стрелять с места. Проверить предпосылки через engine queries до действий.
3. Движущийся NPC сам выбирает goal production callback. Тест не записывает
   combat.goal/reload.goal. Зафиксировать начальный deadline/attempts.
4. Дать ход второму NPC: при подходящих условиях он выполняет aim/fire,
   сохраняя позицию. Затем первый продолжает свой настоящий маршрут.
5. Чередовать решения в обоих порядках ID. Проверять, что оба не прекращают
   движение ради взаимного прикрытия, попытки не возрождаются, а достигнутый
   результат не зависит от повторного создания тестовых таблиц.
6. Повторить с реальным пустым оружием у движущегося и запасным магазином:
   движение к прикрытию → реальная перезарядка → прекращение поддержки.
7. В отдельном опыте заблокировать маршрут/линию огня. Отсутствие подходящего
   решения должно приводить к ограниченному отказу, а не к вечному ожиданию.

Одновременное нахождение двух ботов на арене и seeded goal этого критерия
не заменяют. Фиксировать общую давность наблюдений; не двигать цель вместе
с сохранённым снимком ради удобства теста.

## Блок C: сохранение между действиями

| Момент | Проверка после восстановления |
|---|---|
| После первого реального шага peer | Те же ID, цель, deadline/attempts; повторного создания бойца нет |
| После aim до выстрела | Те же вещи и боезапас; следующий выбор повторно проверяет роль/видимость, а не считает прежнее прикрытие приказом стрелять |
| После состоявшегося выстрела | Патрон не возвращается; отложенное действие не исполняется второй раз |
| После гибели moving peer | Его сохранённый ID не поддерживает роль; другие участники не возрождают casualty |
| После полного закрытия процесса | Проверка через отдельный reader; новый поиск и новое время жизни не выдаются автоматически |
| Следующий рейд | Нет унаследованного cover record, целей, ожидания или голосовых cooldown предыдущего sequence |

Сначала same-process save/load с реальными действиями. После его успеха —
полный restart в отдельных процессах. Seeded cold checkpoint остаётся полезным
тестом формата, но не заменяет холодный сценарий естественного манёвра.

## Реплики намерений: согласовано на будущее

Пользователь предложил 26.10.2026 добавить голосовые реплики после отладки ИИ.
Игрок видит их в журнале только когда слышит NPC через штатную систему звука.
Реплика соответствует настоящему переходу намерения/действия, а не каждому тику.
Примеры: «Перезаряжаюсь», «Прикрою», «Обхожу», «Контакт потерян».

До реализации проверить штатные API речи/звука в pinned BN. Не заменять звук
безусловным add_msg и не назначать текущую проверку видимости союзника готовой
системой голосовой связи. Реплики должны помогать понять происходящее, не
раскрывать невидимых бойцов вне слышимости и не создавать лишнюю точную
разведку у NPC, которые услышали чужую речь. Порядок связи/подтверждения
совместных действий уточнить при реализации; радиосвязь отдельно.

Критерии приёмки:

- Слышно рядом; не выводится в журнал при подтверждённой неслышимости/глухоте.
- Учтены стены, расстояние, этаж и штатная обработка звука; точные пороги
  выбираются после чтения API и опыта, сейчас не фиксируются выдуманными числами.
- Начавшаяся реальная перезарядка вызывает подходящую реплику; отказ без действия
  не сообщает о несуществующей перезарядке. Начало подхода к укрытию и фактическая
  перезарядка различаются в событиях.
- «Прикрою» привязано к роли; «Обхожу» нельзя говорить для обычного шага назад
  или восстановления линии огня, пока собственного обхода не существует.
- Варианты фраз, cooldown и объединение повторов предотвращают спам. Save/load
  не повторяет уже сказанное и не обходит cooldown; новый рейд не наследует его.
- Голосовой переход не создаёт сам себя повторно через hearing → search → speech;
  реплики не превращаются в бесконечный взаимный шумовой цикл.
- Нет вызова speech на каждом выстреле, тике aim или шаге неизменного маршрута.
- Все реплики локализуются; для русского интерфейса проверяется русский журнал.

Это отложенный этап. Пока отлаживаем само поведение; запуск реализации речи
не является условием приёмки текущей компиляции прикрытия.
