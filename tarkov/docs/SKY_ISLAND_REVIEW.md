# Повторный разбор Sky Island

Проверено по исходникам 20 октября 2026, без запуска самого Sky Island.
Успех наших native-тестов BN не является результатом тестирования чужого мода.

## Версии и происхождение

- Официальный DDA: CleverRaven/Cataclysm-DDA, commit
  `0723f9285fa0080dfe1876cc9c2845919252528c`, каталог data/mods/Sky_Island.
- BN-порт: graysonchao/CBN-Sky-Island, commit
  `9e2f4606f37b1f006ddd70a52d25acfff8b2eb33`. Это отдельный репозиторий,
  а не встроенный мод официального BN. В data/mods нашей закреплённой базы BN
  `554950f3635f50ddd1d32c6e1b6e2bdee9842bd6` Sky Island не найден.
- Оригинал создан TGWeaver, порт — graysonchao. Код и контент этих модов в наш
  проект не копировались; ниже используются идеи и описываются зависимости.

## Механизмы и применимость

| Механизм | Актуальный DDA | BN-порт | Решение для проекта |
|---|---|---|---|
| Вход в рейд | EOC_SKY_ISLAND_MISSION_DIMENSION_SHIFT: сохранение домашней позиции, переход в измерение из sky_island_target_region_settings; затем размещение на местности | teleport.use_warp_obelisk: поиск OMT, обычная телепортация далеко от острова | Отдельное ограниченное пространство BN уже реализовано; геометрию рейда выбираем сами |
| Возврат и сброс | EOC_return_OM_teleport: возврат в default, затем clear_dimension целевого рейдового измерения | Возврат по home_location; в изученном ядре нет reset/delete_dimension | Сохраняем return -> cleanup; наш reset оставляет метаданные для повторяемой очистки |
| Таймер | EOC_constantticking с recurrence, нарастающий счётчик импульсов и предупреждения, затем болезнь/распад | Один минутный Lua hook, накопитель и стадии warp sickness | Оставляем абсолютный deadline и жёсткий таймаут; используем идею предупреждений |
| Смерть | PREVENT_DEATH, u_prevent_death, incorporeal для потери вещей, лечение и отложенный возврат | on_character_death: немедленное восстановление HP, drop_all_items, возврат и краткая стабилизация | Немедленное снятие смертельного состояния и потеря комплекта уже есть; не переносим чужой баланс и бессмертие дома |
| Нормальный перенос экипировки | Персонаж путешествует со своими предметами | Персонаж путешествует со своими предметами | Продолжаем переносить настоящие объекты BN; полные JSON-снимки уже проверяются |
| Дополнительный груз из комнаты | u_map_run_item_eocs переносит предметы, затем item_travel_radius переносит их между измерениями | detach_item_at -> временная Lua-таблица detached_ptr -> add_item дома | Возможный будущий грузовой выход; сейчас эвакуируется только переносимое игроком |
| Защищённый контейнер | secure_container.json: INTEGRATED, integrated_armor и pocket_data | В death path сохраняются количества отдельных валютных предметов и создаются заново | DDA JSON не переносится в BN напрямую. Пересоздание по ID подходит только для таких счётчиков, не для произвольной экипировки |
| Безопасная высадка | force_safe, временные эффекты материализации, затем отдельный этап landed | Проверка проходимости/воды/пустоты, поиск ближайшей клетки и эффекты защиты | У нас фиксированные точки и проверки API. Проверки загромождённой высадки полезны; невидимость/полёт автоматически не добавляем |
| Выходы и задания | EOC_create_extract, assign_mission, настройки расстояний и mapgen | Создание миссий из Lua и поиск выхода; распознавание миссий по отображаемому имени | Берём организацию как справочник будущего слоя. Нужны устойчивые ID, не имена/локализация |
| Убежище | island_upgrades через mapgen_update и миссии | Собственные Lua/JSON upgrades и строительство | Источник примеров позднего слоя, не зависимость нынешнего рейдового цикла |
| Загрузка | Глобальные переменные/эффекты/EOC сохраняет DDA; game_load EOC проверяет версию | game.mod_storage, on_game_load и защита от повторной регистрации hook | Подтверждает принцип сохранённого состояния. Не заменяет нашу проверку BN в двух процессах |

В DDA отдельные измерения содержат процедурный мир; это не готовый механизм
наших ограниченных вручную сделанных локаций. Идентичность идеи не означает
совместимость EOC DDA с Lua API BN.

## Что использовать сейчас

1. Порядок «уйти из рейда, затем очистить его» уже соответствует изученному DDA.
   Наши sequence/settled и повторяемый cleanup нужны для отказов записи и загрузки
   checkpoint. Счётчики побед в EOC возврата сами по себе не доказывают такой защиты.
2. Добавлены собственные предупреждения за 5 минут и за 1 минуту. В state хранится
   time_warning: после загрузки сохранённой отметки предупреждение не дублируется.
   Если долгий ход перескочил обе границы, показывается актуальное срочное сообщение.
   Таймаут сохраняется и при неудавшейся эвакуации. Это оригинальная Lua-реализация,
   не перенос болезни, периодического счётчика или текстов Sky Island.
3. Остаётся проверка полного закрытия и загрузки BN. В рассмотренном коде Sky Island
   нет готового тестового стенда для нашего Lua-модуля и измерений BN. Заявление
   README BN-порта о persistence не является нашим воспроизводимым результатом.

Предупреждения проверены локальными fixtures. В native-сценарии прошла загрузка
активного рейда с минутой до deadline: настоящий tick выставляет time_warning,
не продлевая время. Новый рейд сбрасывает отметку. Полный прогон BN успешен:
[39486623922](https://github.com/ProxysRE/CataclysmAI-BN/actions/runs/39486623922),
код d5ee39a54886f7c968a7fe4cf84f63af7655befb. Это проверка нашего модуля, не запуск Sky Island.

## Что не копировать без отдельной задачи

- EOC DDA не заменяет нужные bindings BN; отдельный порт движка не требуется для
  уже работающего у нас цикла.
- Временная таблица owning detached_ptr в BN-порте удерживает предметы во время
  синхронной телепортации. Это не сериализуемый склад и не протокол восстановления
  после закрытия процесса. Не путать её с обычными не владеющими ссылками Item/Map.
- В EOC_skyisland_versioncheck есть проверка состояния «дома» перед обновлением.
  В том же файле EOC версии также имеет собственную подписку game_load; порядок
  совместного выполнения здесь не проверялся. Для изменения наших карт полезна
  явная точка миграции в убежище, а не слепое копирование этой цепочки событий.
- Лечение от смерти в DDA включает калории, жажду, кислород, кровь и другие причины
  повторной смерти; BN-порт стабилизирует HP/эффекты 10 секунд. Для нашего режима
  нужны отдельные проверки причин смерти, а не обещание полного покрытия по одному HP-тесту.
- Изученные ядра используют обычных существ, миссии и перенос спутников. Они не
  дают готового боевого контроллера ЧВК для нашего следующего слоя.
