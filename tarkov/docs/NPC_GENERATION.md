# Генерация проектных противников

Принято пользователем: свои пулы статов, навыков, HP отдельных частей тела и
согласованных комплектов. Разнообразие внутри роли обязательно; случайные
ванильные добавки не являются способом его получить. Реализация полного
генератора ещё впереди, текущий combat tester её не заменяет.

## Что ещё делает закреплённая BN

Аудит BN 554950f3635f50ddd1d32c6e1b6e2bdee9842bd6:

| Участок | Остаточное поведение | Следствие |
|---|---|---|
| npc_class::roll_strength/dexterity/intelligence/perception | dice(4,3) + bonus | Даже постоянный bonus не задаёт точный стат |
| npc::randomize | Случайные aggression/bravery/collector/altruism | Собственный класс не фиксирует характер |
| npc::randomize | mod_skill_level(barter, rng(2,4)) после классовых навыков | Даже ALL=0 не убирает ванильную прибавку |
| npc::randomize | set_body/recalc_hp, затем классовые traits/mutations/bionics | HP и особенности нужно проверять после формирования тела |
| starting_weapon/clothes/inv | Классовые overrides, иначе fallback-группы | Отсутствие поля может вернуть ванильное снаряжение |
| load_npc_template | Вызывает randomize, затем применяет faction/attitude | Контроль должен охватывать весь путь создания |

Источники: [npc.cpp](https://github.com/cataclysmbn/Cataclysm-BN/blob/554950f3635f50ddd1d32c6e1b6e2bdee9842bd6/src/npc.cpp),
[npc_class.cpp](https://github.com/cataclysmbn/Cataclysm-BN/blob/554950f3635f50ddd1d32c6e1b6e2bdee9842bd6/src/npc_class.cpp).

## Контракт будущего генератора

1. Профиль определяет допустимые статы, навыки, базовые HP по частям тела и
   особенности. Неуказанное значимое поле отклоняется либо получает явно заданное
   проектное значение, а не случайный vanilla fallback.
2. Комплект задаёт совместимые оружие/обвесы/магазины/боеприпасы, защиту, одежду,
   средства переноски, медицину и расходники. Проверяется, что предметы можно
   использовать и носить; нельзя собирать набор независимыми несогласованными бросками.
3. Варианты внутри профиля выбираются с весами и ограничениями роли. Уровень
   снабжения остаётся понятным; разнообразие не означает случайный винегрет.
   Боссы и свита могут иметь закреплённую узнаваемую основу и отдельные вариации.
4. Выбор выполняется только при первом создании. В простых метаданных хранятся
   идентификатор/версия профиля и выбранного варианта. Изменяемые HP, навыки и вещи
   сохраняет сам BN; загрузка не должна повторно применять стартовые значения.
5. Готовое место deployment остаётся занятым после смерти. В проектном рейде
   допускаются участники manifest; посторонние ванильные спавнеры не должны
   добавлять случайных противников. Технические нейтральные тесты сохраняются отдельно.

## Условия приёмки

- Разные seed дают разрешённые варианты без выхода за пулы и без скрытой прибавки
  торговли, случайных мутаций, лишнего оружия или непредусмотренных предметов.
- До публикации участника в активном мире проверяются все выбранные параметры,
  совместимость комплекта и max/current HP каждой управляемой части тела.
- После ранения, расхода патронов и полного рестарта сохраняются тот же ID,
  фактические HP, состояние и состав вещей. Новая версия профиля не лечит старого НПС.
- Смерть и replay deployment не создают копию; новый рейд получает новый выбор.
- Большая переработка тактики остаётся отдельной работой. Генератор поставляет
  профиль/роль, но наличие профиля само по себе не означает умный боевой ИИ.


## Первый реализованный шаг: attribute_profile

Патч 0004 добавляет в npc_class необязательный attribute_profile с обязательными
объектами stats и personality. Четыре стата задаются целыми значениями 1..100,
четыре параметра характера — -100..100. Пропущенное поле или значение вне границ
отклоняется JSON loader. Это технические границы, не игровой баланс.

При создании класса с профилем базовые статы не бросаются через 4d3, характер не
получает случайные/legacy прибавки, универсальный +2..4 barter не применяется.
Остальные навыки берутся из явно заданных классовых распределений. Классы без
профиля сохраняют обычный путь, в том числе порядок случайных бросков характера.

Профиль применяется только npc::randomize при создании. Загрузка существующего
участника не вызывает его повторно и не заменяет изменённые параметры стартовыми.
Боевой образец использует статы 10/10/8/10, характер 5/10/0/0 и прежние gun/rifle=6.
Проверки параметров до/после save/load, восьми повторных созданий и неправильных
JSON-профилей добавлены в native gate. Его результат для патча пока ожидается.

Это ещё не полный генератор: сейчас один фиксированный профиль, HP остаются
формулой BN, внешность/имя и прочие непокрытые параметры не контролируются.
Взвешенные пулы профилей, HP по частям тела, варианты комплектов, проверка полной
совместимости и подавление сторонних спавнеров остаются будущими задачами.


## Следующий шаг: hit_points в профиле

attribute_profile теперь может содержать hit_points с обязательными head, torso,
arm_l, arm_r, leg_l, leg_r. Все значения — целые 1..10000. Без таблицы HP остаётся
обычный расчёт BN; неполная таблица или нулевой максимум отклоняются загрузчиком.
Текущий боевой образец получает 35/85/60/60/65/65. Это технические значения для
шести основных частей BN, не окончательная модель здоровья Tarkov. Отдельного
живота пока нет; глаза/рот/кисти/стопы наследуют максимум своей основной части.

После формирования тела, traits/bionics/spells npc::randomize записывает выбранные
максимумы в Creature values npc_profile_hp_<part>, пересчитывает HP и создаёт
полностью здорового участника. Повторный randomize очищает прежние HP-метки.
Обычная загрузка не выполняет этот шаг. Values сохраняются вместе с участником,
поэтому изменение шаблона не подменяет выбранные максимумы существующего НПС.

Character::calc_all_parts_hp учитывает эти сохранённые значения только для NPC.
Сила, мутации, skill boosts и enchantments не меняют явный максимум. Если максимум
тот же, текущие HP не трогаются, в том числе чтобы float/ceil не залечивал один
пункт при повторных пересчётах. При отсутствии метки сохраняется обычный расчёт.
Для повреждённой или нестандартной анатомии вне перечисленных основных частей
полный профиль ещё не предусмотрен. Весовые пулы и разнообразие комплектов впереди.

Native-проверки включают все части созданного тела, повторное создание, повреждение
руки до 17 HP и сохранение/загрузку с recalc_hp. В трёхпроцессном стенде отдельному
нейтральному НПС напрямую задаётся сохранённая HP-метка головы 35 и ранение до 21:
это проверяет механизм хранения/пересчёта в новом процессе отдельно от реального
создания боевого профиля. Результаты этих новых native-сценариев ещё ожидаются.


## Первые согласованные комплекты

trkv_loadouts задаёт версионированные варианты целиком, с выбором через gapi.rng:

| ID | Вес | Оружие | Одежда | Дополнительные вещи |
|---|---:|---|---|---|
| rifle_civilian_v1 | 3 | AR-15, 17×223 | jeans/tshirt/sneakers | Нет |
| rifle_field_v1 | 1 | M4A1, 30×223 | pants_cargo/hoodie/sneakers | Два stanag30 по 30×223 |

Оба оружия принимают STANAG и этот боеприпас на закреплённой базе. Запасные
магазины входят в ограниченный набор; объём грузовых штанов и худи оставляет
место для них. Полная проверка переноски/обвесов/защиты/медицины пока не реализована.
Field-класс наследует статический профиль статов/HP технического стрелка, меняя
только три equipment override. Это технические варианты одного уровня, не баланс
сторон и не окончательные наборы ЧВК/Диких. Существующие v1 нельзя молча менять
при дальнейшем развитии каталога: новые правила получают новый идентификатор.

deployment выбирает loadout до spawn и записывает его в creating-slot. Затем ID
переходит в ready-slot и запись участника; актёр получает тот же Creature value
trkv_loadout. При восстановлении creating учитываются sequence, slot и выбранный
loadout. Готовое место не перебрасывается и после смерти остаётся занятым. Для
старых мест без loadout сохраняется прежнее восстановление без нового выбора.

Запись в Lua перед spawn не является отдельной транзакцией сохранения. Окно до
записи движком и окно до постановки тегов по-прежнему не дают полного crash recovery;
нулевой или неоднозначный поиск не вызывает слепой повтор создания.

Локальные проверки покрывают границы весов, оба шаблона, сохранение выбора при
прерывании и несовпадающие теги. Native gate дополнен одеждой, оружием, боезапасом,
запасными магазинами, обоими классами в повторных randomize и сохранением выбранного
набора после стрельбы/load. Native-результат этих изменений ожидается.


## Пул подготовки и комплектов (22.10.2026)

HP прошли Windows 39826840104 и Linux 39826840074. Два исходных комплекта,
их создание из production JSON, стрельба и save/load прошли Windows 39829355420.
Предыдущие формулировки об ожидании в разделах выше относятся к истории этих шагов.

Каталог теперь выбирает полный вариант «профиль подготовки + комплект» одним
взвешенным броском 1..12. Эти веса технические и не задают итоговую сложность рейдов.

| Сохранённый ID варианта | Профиль | Комплект | Вес |
|---|---|---|---:|
| rifle_civilian_v1 | rifle_trained_v1 | civilian_v1 | 3 |
| rifle_field_v1 | rifle_trained_v1 | field_v1 | 1 |
| rifle_recruit_civilian_v1 | rifle_recruit_v1 | civilian_v1 | 6 |
| rifle_recruit_field_v1 | rifle_recruit_v1 | field_v1 | 2 |

trained сохраняет прежние статы 10/10/8/10 и gun/rifle=6. recruit получает
8/8/8/8 и gun/rifle=3. Все остальные навыки явно нулевые. Характер и HP пока
одинаковы у обоих профилей: 5/10/0/0 и 35/85/60/60/65/65. Это демонстрирует,
что меньшая сила не обязана уменьшать профильные HP. Названия технические,
это не утверждённые категории ЧВК/Диких и не новый тактический контроллер.

На обоих уровнях подготовки соотношение комплектов 3:1. Общая доля recruit 2/3,
trained 1/3; качество оружия не фиксирует подготовку. Прежние два ID и их JSON-классы
не меняются. Новые recruit-классы наследуют контролируемую основу, явно заменяют
статы и навыки; field-вариант меняет только оборудование. Каталог describe возвращает
копию описания, не открывая внутреннюю таблицу для изменения.

В storage остаётся строковый loadout полного варианта. Отдельный несогласованный
бросок профиля при загрузке не выполняется. Сами параметры и изменённые навыки
хранит BN; describe только сообщает смысл выбранного ID, ничего не применяет заново.
Смена весов не должна менять сохранённый выбор.

Fixture перечисляет все 12 исходов, проверяет четыре шаблона и восстановление
recruit-вариантов без RNG. Native gate расширен до 12 созданий с чередованием
всех четырёх классов и проверкой каждого навыка, статов, HP и комплекта. В живом
боевом сценарии после стрельбы gun/rifle меняются на +1, barter на 2, рука ранится
до 17: reload/replay должен сохранить их, а новый НПС получить исходный профиль.
Локальные проверки прошли; native-результат нового пула ещё ожидается. Полный
холодный рестарт четырёх боевых вариантов и перезарядка запасным магазином впереди.


## Первый запрет внешнего спавнера (22.10.2026)

Пул подготовки прошёл Windows 39838851214 и Linux 39838851216, включая сборку,
native/cold/NPC сценарии. Исправление include skill.h подтверждено этими прогонами.

Аудит закреплённого game.cpp выявил вызовы perhaps_add_random_npc в обычном ходе
и обработке активности. Спавнер проверял только опции мира и время, не правила
рейдового пространства: даже ограниченный тип измерения мог получить странника,
новую solo-фракцию и случайное задание. Патч 0005 добавляет свойство типа мира
allow_random_npcs=true по умолчанию, false для trkv_raid_space. Проверка выполняется
до бросков, генерации НПС и его фракции. Влияет также на проектное убежище.

Это запрет одного конкретного автоматического пути, не общий firewall НПС.
Остальные найденные источники:

| Путь закреплённой BN | Текущее правило / дальнейшая работа |
|---|---|
| JSON place_npcs → map::place_npc | Явные шаблоны, STATIC_NPC; наши технические карты не содержат place_npcs. Разрешения для будущего mapgen ещё нужны |
| gapi.spawn_npc_at → place_npc(force=true) | Нужен нашему deployment, флаг random не блокирует |
| create_starting_npcs и спутники профессии в game::start_game | Будут согласованы с переработкой создания персонажа; не контролируются новым флагом |
| spawn_hallucination (ветка NC_HALLU), debug/миссии/скрипты | Новый флаг их не блокирует; требуется отдельная проектная политика |
| Уже сохранённые НПС и путешествия между измерениями | Флаг не удаляет и не фильтрует их; перенос и проверка manifest ещё впереди |

Native gate напрямую вызывает почасовой спавнер двенадцать раз на точной границе
часа, при RANDOM_NPC=true и NPC_DENSITY=100 (обычная вероятность при малом числе
НПС равна 1). Проверка повторяется после save/load с живым production-противником;
число НПС не должно расти. Время тест временно меняет и восстанавливает, Lua hooks
таймера рейда при этом не исполняет. Cold reader дополнительно проверяет флаг
загруженного типа. Эти новые native-проверки ещё ожидают компиляции и исполнения.
