# Проверка данных локаций в клиенте Таркова

Инициировано пользователем 25.10.2026. Цель — получить точные пространственные
референсы Завода вместо дальнейшего угадывания высот и дверей по плоской схеме.
К реальной установке клиента пока доступа нет; перечисленное ниже — план,
а не результат извлечения Factory.

## Что известно о формате Unity

Первичный источник Unity:
https://github.com/Unity-Technologies/UnityDataTools/blob/main/Documentation/assetbundle-format.md

Сцена может содержать иерархию GameObject/Transform и ссылки на другие объекты.
Внешние данные сцены, модели и материалы могут находиться в отдельных
SerializedFile/AssetBundle. Нужно восстанавливать ссылки между контейнерами,
а не считать один файл с именем factory полной локацией. Официальные инструменты:
https://github.com/Unity-Technologies/UnityDataTools
Дополнительный парсер, который можно оценить после определения версии данных:
https://github.com/K0lb3/UnityPy

Версия Unity, наличие type trees, способы размещения сцен и динамической сборки
Таркова пока неизвестны. Возможность прочитать все нужные компоненты не обещается
до первого образца. Наличие визуальной геометрии на клиенте не означает, что там
есть все серверные правила, состояния дверей, выходов, ИИ и появления объектов.

## Первый шаг: небольшой отчёт о контейнерах

Подготовлен стандартный Python-скрипт, без установки сторонних библиотек:

```powershell
py inspect_tarkov_client.py "D:\Games\Escape from Tarkov" --output tarkov_client_inventory.json.gz
```

Путь — пример; указать фактическую папку установленной игры. Можно передать сам
`EscapeFromTarkov_Data`. Выходной файл должен быть новым: старый отчёт не
перезаписывается. Сканер не запускает игру, не подключается к её процессу и ничего
не отправляет по сети. Исходные файлы не меняются.

Он записывает относительные имена, размеры, версии из заголовков Unity-пакетов,
имена подходящих сцен/ресурсов/манифестов и совпадения factory в путях. Заголовок
каждого bundle читается максимум на 256 байт; содержимое моделей не извлекается.
DLL, профили лаунчера, аккаунт, игровые настройки и логи не собираются. Папки вне
указанного Data-каталога не обходятся. Ссылки и распознаваемые junction пропускаются.

На синтетической папке проверены: обнаружение bundle и scene-контейнера,
определение версии Unity, исключение Managed DLL, чтение сохранённого gzip JSON,
отказ перезаписывать существующий отчёт. Это проверка сканера, не клиента Таркова.

## Что искать дальше

| Данные | Зачем нужны |
|---|---|
| Сцены и зависимости | Найти все части Завода и общие объекты |
| Transform и родительская иерархия | Вычислить мировые координаты с учётом поворотов и масштаба |
| Mesh и Collider | Отделить видимую поверхность от физической преграды |
| Полы, мостки, лестничные пролёты | Восстановить высоты и реальные подходы |
| Объекты дверей и интерактивные компоненты | Найти положение и ориентацию дверей, затем уточнить поведение |
| Terrain и внешние участки | Проверить полноту дворов и границ карты |

После инвентаризации выбираем минимальный набор контейнеров Завода и их
зависимостей. Только затем пробуем чтение объектов. Промежуточный результат —
не текстуры и не вся установка, а компактная таблица объектов и пространственных
связей с источником каждого объекта. Сначала сверяем несколько известных точек
и этажи; затем строим проекции для сетки BN.

Правила конвертации: Unity y-up не превращается в z BN простым переименованием
компонент; нужен проверенный поворот/масштаб/сдвиг. Неравномерный scale родителя
меняет коллайдеры. Отдельно учитывать выключенные объекты, LOD, декоративные
меши, дверные состояния, отверстия и скриптовую сборку. Текстуры сами по себе
не определяют проходимость. До проверки это не автоматический перенос локации.
