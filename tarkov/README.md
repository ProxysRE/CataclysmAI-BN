# Tarkov Project — DEV0.1

Самостоятельная игра на базе Cataclysm: Bright Nights с рейдовым режимом. Рабочее название.
Поставляется своей Windows-сборкой; JSON/Lua-модули остаются внутренней организацией.
Каталог не относится к LLM/Narrative-проекту в корне репозитория или к переносу DDA.

## Первый срез

Реализован исходный прототип: постоянное убежище, отдельная ограниченная карта 24×24,
вход со своим инвентарём, предмет добычи, эвакуация, поражение, таймер 30 игровых минут
и сброс территории между рейдами. Карта техническая, это ещё не Завод.

**Статус:** базовый цикл и холодная загрузка прошли настоящий BN на Linux в
[прогоне 39511333415](https://github.com/ProxysRE/CataclysmAI-BN/actions/runs/39511333415).
Основной testcase прошёл 61 проверку C++; три отдельных процесса — ещё 45.
Проверены активный рейд после полного перезапуска, сохранность дедлайна, оружия,
добычи и шкафа, восстановление очистки и следующий рейд. Исправление движка
восстанавливает границы в буфере правильного измерения.
Пользователь подтвердил создание мира, вход и эвакуацию через Windows-интерфейс.
Windows native и холодная загрузка прошли в 39646723414, русский пакет собран.
Остаётся объединённая ручная приёмка. Начат изолированный тест участника второго слоя.
Подробности — `docs/VERIFICATION.md`.

## Версия BN

Точная база: `554950f3635f50ddd1d32c6e1b6e2bdee9842bd6` (19 октября 2026).
Не обещаем совместимость с любой stable/nightly. Требуется production-патч
`patches/0001-restore-bounds-to-target-dimension.patch`: он исправляет восстановление
границ при холодной загрузке. Исправление прошло Linux native CI, включая холодную загрузку. Одного копирования файлов мода в штатный executable недостаточно.

## Запуск на Windows

Workflow `.github/workflows/tarkov-windows.yml` готовит portable ZIP на Windows x64.
Он проверяет статическую SDL, `--version` и загрузку мода из установленной папки.
Пакет 6d35b496 успешно собран в 39609962500; базовый вход/выход проверен пользователем.
Пакет 1444b2c в 39646723414 включает проверенные каталоги русского языка BN и мода,
а также прошедший Windows native/cold gate. Визуальная приёмка русского интерфейса ещё впереди.

1. Использовать архив из успешного Windows workflow и распаковать его в отдельную папку,
   либо собрать BN на указанной базе с патчем из `patches/`.
2. В архиве мод уже включён. Для самостоятельной сборки скопировать
   `mods/trkv_raid_core` в её `data/mods/trkv_raid_core`.
3. Создать **новый отдельный мир**, включить `Tarkov Project: DEV0.1 raid foundation`.
4. Создать обычного персонажа. После старта он переместится в тестовое убежище.
5. Осмотреть терминал отправления у центра комнаты и выбрать рейд.
6. Забрать тестовый пакет со стойки в северо-западной части карты.
7. Добраться до зелёного маркера в юго-восточном углу и осмотреть его.
8. Оставить пакет в шкафу убежища и повторить рейд: пакет на карте должен появиться снова.

Если первый вход завершился ошибкой, повторно осмотреть терминал и выбрать
`Retry pending raid entry`. Это повтор той же попытки; время ожидания в убежище
не отнимает время нового входа. Проверено настоящим BN на закреплённой базе.

В текущем прототипе смерть/таймаут теряют весь переносимый комплект и возвращают
персонажа с 30 HP на часть тела. Защищённого контейнера и страхования ещё нет.
Само убежище не даёт бессмертия. Базовый рейд пустой; для технических проверок
в терминале предусмотрены отдельные патрульный и боевой режимы.
Между рейдами не выдаются награды, деньги или новое снаряжение.
За пять минут и за минуту до таймаута появляются предупреждения с оставшимся временем.

## Проверки

```sh
python -m pip install lupa==2.6
python tarkov/tools/check.py
python tarkov/tools/install_into_bn.py /path/to/pinned-bn --tests
```

Последняя команда устанавливает мод и тестовый overlay в отдельный checkout BN,
не перезаписывает существующий мод и проверяет SHA основы. Она применяет обязательный
патч движка также без `--tests`; после установки нужно пересобрать BN.
Workflow `.github/workflows/tarkov-dev01.yml` собирает BN и его тестовый executable,
проверяет загрузку JSON и выполняет `[tarkov]` с настоящей картой, аватаром и SQLite-миром.
Затем `tools/run_cold_restart.py` проверяет три отдельных запуска над закрытыми
копиями временного мира. Windows-проверки описаны в `docs/WINDOWS_VALIDATION.md`.

## Следующий игровой срез: патрули

В терминал добавлен отдельный пункт «Войти в тестовый рейд с патрулями
(3 нейтральных НПС)». Для него используются собственные шаблон, класс и фракция
участников, общий реестр и соседние точки маршрута. Базовый пустой рейд доступен
прежним пунктом. Это техническая проверка, не окончательные отношения USEC/BEAR.

Нужна новая сборка с патчем 0002, добавляющим активное создание НПС из Lua.
Игровой путь с собственными шаблонами прошёл Linux 39703436026 и Windows
39703436006. Следующее расширение маршрутов требует также патча 0003: один шаг
по пути к дальней точке, с открытием дверей. Проход через дверь, загрузка в пути
и обход стены прошли Linux 39773784219 и Windows 39773784240. Встречные маршруты,
ожидание занятой клетки и продолжение после загрузки прошли Linux 39780286066 и
Windows 39780286033. Гибель НПС, выпавшие вещи, отсутствие возрождения при загрузке
и эвакуация захваченного оружия прошли Windows 39789218037; Linux-прогон ещё идёт.
Следующее расширение добавляет живых и погибшего участников в проверку полного
перезапуска игры тремя отдельными процессами; его native-результат ожидается.


## Боевой тестовый рейд

В терминале добавлен пункт «Войти в боевой тестовый рейд (1 враждебный стрелок)».
Он создаёт одного противника в восточной части площадки, за стеной от точки входа.
Комплект выбирается целиком: AR-15 с 17 патронами и лёгкой одеждой либо M4A1
с 30 патронами, грузовыми карманами и двумя запасными магазинами. Маршрут короткий. При
обнаружении игрока управление получает штатный боевой ИИ BN. Это технический
противник, без окончательной дипломатии USEC/BEAR и без новой тактической системы.
Пустой рейд и режим трёх нейтральных патрульных доступны прежними пунктами.

Режим сохраняется при повторе неудавшегося входа и загрузке. Снаряжение задаётся
JSON-группой при создании; загрузка не выдаёт новое оружие и не пополняет патроны.
Реальная стрельба, сохранение расхода патронов, фиксированные атрибуты, HP и оба
комплекта прошли Windows в [39829355420](https://github.com/ProxysRE/CataclysmAI-BN/actions/runs/39829355420).
HP-профили также прошли Linux 39826840074. Linux-прогон комплектов 39829355413 ещё
выполняется. Это автоматические проверки движка, отдельная ручная приёмка не заявляется.

Следующее расширение добавляет пул подготовки: технический стрелок с gun/rifle=6
и рекрут с gun/rifle=3, каждый с любым из двух согласованных комплектов. Выбор
сохраняется как versioned ID полного варианта; прежние ID сохраняют значение.
Профили имеют разные статы и одинаковые явные HP — это временные исходные
параметры НПС, а не переработка механики характеристик персонажа. Пул прошёл Windows 39838851214 и Linux 39838851216, включая native/cold/NPC gates. Броня, медицина, обвесы, состояние
вещей, полные пулы снабжения и новая тактика остаются дальнейшей работой.


## Запрет случайных НПС в проектном пространстве

Патч 0005 добавляет world_type.allow_random_npcs (по умолчанию true). Для
trkv_raid_space задан false: почасовой game::perhaps_add_random_npc не создаёт
ванильных странников даже при включённых RANDOM_NPC/NPC_DENSITY. Явное создание
наших участников остаётся через spawn_npc_at и production-шаблоны.
Локальные проверки прошли; компиляция и native-проверка нового запрета ожидаются.
Это ограничение конкретного динамического спавнера. Mapgen/миссии, галлюцинации,
миграция/путешествия и стартовые спутники не становятся автоматически разрешёнными
проектными участниками; общий запрет всех внешних источников ещё впереди.
