# DEV0.3 fix08: predecessor furniture cleanup

Uploaded Save(1).zip (Apollo world) contains 59 flower furniture objects on pavement in generated highway cells. All 48,013 directly mapped cloverleaf terrain cells matched the imported DDA template, with no grass replacing template pavement. Three saved adjacent highway seams matched; no reserved overmap terrain remained. Up/down low/high ramps were each present in 92 saved terrain cells.

Cause: mapgen_function_json::generate and mapgen_function_json_nested::nest only constructed a flags-bearing context when their argument maps were nonempty. Thus argument-free highway templates lost ERASE_ALL_BEFORE_PLACING_TERRAIN, leaving predecessor field/forest flowers over newly placed pavement.

Fix: only reuse the incoming context when both arguments AND flags are empty. Otherwise use the existing context constructor, including for nested mapgens. Preserve geometry, grassy cloverleaf interiors and all source flags.

Regression: seed guaranteed flower furniture over every cell before reapplying a real highway template. Assert pavement and guardrail cells have null furniture across four rotations and both ground/elevated predecessor cases. This does not rely on random field flower spawning.

Local dependency closure, unchanged DDA geometry, paired ramps and median checks pass. Windows game and tests must pass before replacement packaging. Existing generated save terrain is not regenerated by this source fix.
